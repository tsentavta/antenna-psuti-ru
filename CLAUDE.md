# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Static Hugo site for the Department of Radioelectronic Systems, PSUTI (ПГУТИ), rebuilt from a dead PHP/DB CMS. All content, comments, commit messages and UI text are in Russian — keep it that way.

## Commands

There is no test suite, linter or package.json. Only Hugo (extended) is needed; CI pins `HUGO_VERSION` in `.github/workflows/deploy.yml`.

```bash
hugo server                  # dev server at http://localhost:1313
hugo server --buildDrafts    # include draft: true pages (unverified 2018 data)
hugo --minify                # production build into public/
npx -y pagefind@1 --site public   # search index; run after every build, otherwise /poisk/ search is empty
```

Reproduce the GitHub Pages build exactly (site lives in a subpath):

```bash
hugo --minify --baseURL "https://tsentavta.github.io/antenna-psuti-ru/"
```

Deploy is automatic: pushing to `master` (or `main`) runs `deploy.yml` → GitHub Pages. The default branch is `master` (README mentions `main`; the workflow accepts both).

## Architecture

- **Subpath hosting.** Content links are written root-relative (`/uploads/…`, `/labs/…`); `canonifyURLs = true` in `hugo.toml` rewrites them against `baseURL`. In templates always use `relURL`/`.RelPermalink`, never hardcoded `/…` paths. `.nojekyll` must stay.
- **Recovered content is raw HTML.** Most `content/**/*.md` files contain HTML from the old CMS (with a `<!-- восстановлено из: … -->` provenance comment), so `markup.goldmark.renderer.unsafe = true` is required. URL = path under `content/`; sections are `_index.md`.
- **Custom front matter** (handled in `layouts/_default/{single,list}.html`, `layouts/index.html`):
  - `draft: true` + `reviewNote` — 2018 staff/schedule/thesis data not to be published until verified by the department; `reviewNote` renders as a yellow banner.
  - `emptyPage: true` — show a "being prepared" placeholder instead of empty body.
  - `hideInMenu`, `weight` (menu order), `attachments: [{name, file}]`.
  - `oldAlias` — slug from the old `index.php?page=<slug>` URLs.
- **Old-URL redirects.** `data/routes.json` maps old `?page=` slugs to new paths. Consumed in three places: `static/.htaccess` (real 301 on Apache), `static/index.php` (JS fallback, has its own inlined copy of the table), and `layouts/index.html` (JS on the home page via `hugo.Data.routes`). They are generated by `../rebuild/recover/gen_redirects.py`, which is **not in this repo** — if a page is moved/renamed, update all of them by hand. The same applies to the archive-recovery scripts (`../rebuild/recover/*`) mentioned in the README.
- **Interactive labs** (`content/labs/{classic,modern}/*.md`, layout `layouts/labs/single.html`). Each lab exists in two lines: `classic` (recreation of the 2001 Java-applet stand, with per-lab CSS where control coordinates are tied to the equipment image) and `modern` (redesigned model). Front matter wires the pieces together:
  - `model: "<name>-<line>"` → partial `layouts/partials/labs/<model>.html` (markup)
  - `script: "js/lab-<name>-<line>.js"` → `assets/js/` (vanilla JS, canvas plotting)
  - `styles: "css/lab-<name>.css"` (classic only) → `assets/css/`
  - `altVersion: {note, label, url}` → link to the other line
  Assets go through Hugo Pipes with `fingerprint` for cache-busting — keep new CSS/JS in `assets/`, not `static/`. Lab JS reads colors from site CSS variables so plots follow the accessibility color schemes.
- **Accessibility mode** (`partials/a11y-bar.html`, inline script in `baseof.html`, `assets/js/site.js`): settings stored in `localStorage["a11y"]` and applied as `data-*` attributes on `<html>` before render; CSS in `assets/css/main.css` keys off them.
- **Admin** (`static/admin/`): Sveltia/Decap-compatible CMS, GitHub backend on `master`, `publish_mode: simple` (commits straight to master), OAuth via a Cloudflare Worker (`base_url`). Uploads go to `static/uploads/`. When adding front-matter fields, also add them to `static/admin/config.yml` collections.
- **Site settings caveat:** the admin's "Настройки сайта" edits `data/site.yml`, but templates read department/address/phone from `[params]` in `hugo.toml` (`.Site.Params.*`) — `data/site.yml` is currently not used by any template. Change both, or wire templates to `hugo.Data.site`.

# Сайт кафедры радиоэлектронных систем ПГУТИ

Статический сайт на Hugo. Ни PHP, ни базы данных: нечему устаревать и нечего
взламывать — именно это погубило прежний сайт.

## Что нужно установить

Только [Hugo](https://gohugo.io/) (один исполняемый файл):

```bash
winget install Hugo.Hugo.Extended
```

## Посмотреть сайт у себя

```bash
hugo server
```

Откроется на `http://localhost:1313`. Правки в файлах видны сразу,
перезапускать ничего не надо.

## Как устроено

| Каталог | Что внутри |
|---|---|
| `content/` | тексты страниц, по одному файлу на страницу |
| `content/novosti/` | новости |
| `layouts/` | шаблоны оформления |
| `static/` | картинки, методички, стили, лабораторные работы |
| `static/admin/` | админка |
| `data/` | контакты и таблица старых адресов |

Адрес страницы повторяет её путь в `content/`. Страница с подразделами
лежит в своём каталоге и называется `_index.md`.

## Админка

Открывается по адресу `/admin/` на опубликованном сайте. Вход по учётной
записи GitHub, отдельного пароля нет.

**Перед первым запуском** откройте `static/admin/config.yml` и замените
`OWNER/REPO` на адрес вашего репозитория, иначе вход не сработает.

В админке три раздела: «Новости», «Страницы» и «Настройки сайта» (контакты
и телефон). Загруженные картинки и файлы попадают в `static/uploads/`.

После нажатия «Опубликовать» изменения появляются на сайте примерно через
минуту — столько занимает пересборка.

## Публикация

Сборка и выкладка идут сами при каждом изменении в ветке `main`
(`.github/workflows/deploy.yml`). Вручную ничего запускать не нужно.

Чтобы включить: в настройках репозитория на GitHub откройте
**Settings → Pages** и в разделе **Source** выберите **GitHub Actions**.

Собрать вручную, если понадобится:

```bash
hugo --minify
npx -y pagefind@1 --site public
```

Готовый сайт окажется в каталоге `public/`. Его можно просто скопировать
на любой обычный хостинг — например, на сервер университета.

## Черновики

Часть страниц помечена `draft: true`: это данные 2018 года, которые нельзя
публиковать без сверки с кафедрой — состав преподавателей, расписание, темы
дипломных работ. Такие страницы не попадают на сайт.

Посмотреть их вместе с остальными:

```bash
hugo server --buildDrafts
```

Когда сведения сверены, уберите `draft: true` в начале файла — или снимите
галочку «Черновик» в админке.

## Старые адреса

Ссылки вида `/index.php?page=kontakty` продолжают работать: на Apache их
переводит `static/.htaccess` настоящим 301, на прочих хостингах — небольшой
скрипт на главной странице. Таблица адресов лежит в `data/routes.json`
и создаётся заново командой:

```bash
python ../rebuild/recover/gen_redirects.py
```

## Наполнение

Тексты 41 страницы пока отсутствуют — они хранились в базе данных, дампа
которой нет. Восстанавливаются из веб-архива:

```bash
python ../rebuild/recover/fetch_archive.py --probe
python ../rebuild/recover/fetch_archive.py
python ../rebuild/recover/to_hugo.py
```

## Публикация на GitHub Pages

Эта папка — копия сайта, подготовленная к публикации. Что в ней уже сделано:

* `canonifyURLs = true` в `hugo.toml` — ссылки в восстановленном контенте
  записаны от корня (`/uploads/…`, `/labs/…`), и при публикации в подпапку
  репозитория им нужно приписать базовый адрес, иначе они дают 404;
* `.nojekyll` — иначе GitHub прогонит сайт через Jekyll и выбросит файлы
  и папки, чьи имена начинаются с подчёркивания;
* `.github/workflows/deploy.yml` — сборка и публикация; базовый адрес берётся
  из `actions/configure-pages`, поэтому имя репозитория нигде не зашито.

Порядок действий:

```bash
git init
git add .
git commit -m "Сайт кафедры радиоэлектронных систем"
git remote add origin https://github.com/<пользователь>/<репозиторий>.git
git push -u origin master
```

Затем в настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
После первого push сборка запустится сама; адрес сайта появится в разделе Pages.

Локальная сборка ровно как на сервере — с тем же адресом, что даст Pages:

```bash
hugo --minify --baseURL "https://<пользователь>.github.io/<репозиторий>/"
npx -y pagefind@1 --site public
```

Без второй команды поиск по сайту работать не будет: индекс строится отдельно.
